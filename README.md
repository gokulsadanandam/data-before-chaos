# Data before Chaos — Golden Customer Record on Microsoft Fabric

EPAM Accelerate Next: Fabric Frontier Hackathon · Track 02 *GenAI Data Harmonization &
Quality Guardrails* · Team **Data before Chaos**

Customer data arrives from six systems (two ERPs, CRM, web, POS loyalty, mobile app) with
duplicates, typos, conflicting consent and placeholder values. This repository turns it
into **one trusted golden record per customer** on Microsoft Fabric, with quality gates,
a human review loop written back from Power BI, and an audit trail for every value. The
golden data then feeds the marketing agent through a Fabric data agent.

```
 landing files ─▶ Bronze ─▶ Silver ─▶ matching ─▶ review (Power BI ⇄ SQL DB) ─▶ Gold (SCD2) ─▶ reports / data agent
   6 sources     as-is     cleaned   Tier 1-3      stewards decide          one per customer
                append-only tokenised  rules+ML+AI                          DQ gate before publish
```

| Tier | What | Fabric feature |
|---|---|---|
| 1 Rules | standardise email / phone (E.164) / country / names, fix typos, flag placeholders, quarantine junk | Spark notebooks |
| 2 Match model | identifier profiling (unique / household / shared), blocking, Jaro-Winkler, Soundex, Jaccard, logistic score, bands | Spark notebooks, MLflow |
| 3 AI | ambiguous pairs only: `ai.similarity`, `ai.classify`, explanations with `ai.generate_response` | Fabric AI functions |
| Human | LOW band + 10% of MEDIUM go to stewards; approve / reject / hold from Power BI | SQL database, User data functions, translytical task flow |
| Govern | 6 DQ rules as a gate + Purview scorecard, alerts, labels, lineage | Purview, Activator, sensitivity labels |

## Results on synthetic data (local run)

`make data run-local` on 2,000 synthetic people (5,169 source records across 6 systems,
with planted households, look-alikes, typos and junk):

| Metric | First run (no steward input) | After 400 steward decisions |
|---|---|---|
| Pair precision (labelled pairs) | 99.9% | 99.9% |
| Pair recall (labelled pairs) | 94.9% | 97.9% |
| Golden records (2,000 real people) | 2,133 | 2,051 |
| Items in the review queue | 405 (7.9% of records) | 5 |
| Records quarantined (placeholders, junk) | 28 | 28 |
| DQ gate (6 rules) | passed | passed |

The local run uses a deterministic stand-in for the AI tier; in Fabric the AI functions
replace it. See `docs/demo-script.md` for how these numbers are shown.

## Quick start (laptop, no Fabric needed)

Requires Python 3.10+ and Java 17 (for local Spark).

```bash
make setup                 # venv + dev dependencies + pre-commit hooks
source .venv/bin/activate
make data                  # synthetic landing files with ground truth -> local_data/landing
make run-local             # full pipeline on local Spark -> local_data/warehouse (parquet)
make ci                    # lint (ruff), types (mypy --strict), tests (pytest)
```

`python -m goldenrecord.local_runner --help` shows options such as
`--simulate-review 400` (answer review items from ground truth, then re-resolve).

## Deploy to Fabric

Follow **`docs/deployment-guide.md`** step by step (about 2 hours the first time):
workspace and Lakehouse → Key Vault secret → Environment with the wheel → upload
`config/` → import notebooks → SQL database + scripts → user data function → mirroring and
shortcut → pipeline → semantic model and reports → Purview rules, Activator, data agent.
`docs/day-1-checklist.md` is the short version for the first session on the sandbox.

## Engineering practices

* **Config, not code:** sources, weights, thresholds, survivorship and DQ rules are YAML;
  adding a source is a config change (`docs/adapting-to-vendor-data.md`).
* **Thin notebooks over a tested library:** notebooks are generated, contain no logic and
  have outputs stripped by pre-commit (`nbstripout`).
* **Quality gates:** ruff (incl. bandit security rules), mypy `--strict`, pytest with
  unit, Spark and end-to-end tests, GitHub Actions on Spark 3.5 and 4.0.
* **Idempotent stages:** Bronze de-duplicates by row hash; Silver and Gold are recomputed
  snapshots (ADR 0003); every stage can be re-run safely.
* **Stable identifiers:** master keys never change or get reused (ADR 0004).
* **Privacy by design:** secrets in Key Vault, HMAC tokens for identifiers, masked review,
  minimal AI inputs, no personal data in logs (`fabric/governance/security_and_privacy.md`).
* **ANSI-safe Spark:** `try_*` functions throughout so behaviour matches on Fabric
  Runtime 1.3 (Spark 3.5) and 2.0 (Spark 4).
